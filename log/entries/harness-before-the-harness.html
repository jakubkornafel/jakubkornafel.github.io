"I don't see the value."

My team lead said it plainly, more than once, and he was not being difficult. He was describing the situation accurately. I was weeks into building something I could not name, whose entire output was the absence of things going wrong.

Try defending that in a conversation about headcount.

Where it started

November 2025. A calendar invite titled "Agentic Coding Setup" — me, Szymon, one more colleague, one hour.

By the working sessions on 24 and 26 November we had the shape of it. The notes from those calls read strangely now: a vendor-agnostic repository of practice so a new person could be productive immediately. A model we called delegate, review, own — the human reviews what the agent produced, and ownership never transfers. Four agents as a first target, each with its own folder, its own tools, its own instructions. Templates for the documents each role hands to the next.

We were not building an agent. We were building the process an agent works inside.

And I should be straight about this: I did not build it alone. Szymon built it with me — the repository structure, the tooling, half the arguments that made it better.

What it actually was

An agentic SDLC framework. The whole path from a raw idea to an implementable architecture package, decomposed into specialised roles that hand work to each other under rules.

Structurally it was a graph. Each role was a node — research, reverse engineering, product definition, architecture, and a reviewer that was deliberately none of them. The edges were typed: work moved forward only if it carried the identifiers that let you trace any claim back to where it came from. State lived in files that outlived any single run, so nothing important lived inside a conversation window. Transitions were gated, and a gate could refuse and send the work back to a named earlier node.

I had no language for that in January 2026. I said "the pipeline" and watched people's eyes glaze.

Why nobody could see it

The exciting approach at the time was the other one: agents let loose on the codebase, no gate, no independent verification, ship whatever comes out. It produced a great deal of code very quickly. It also took the system down every few days, and every few days somebody lost an evening finding out why.

Our pitch, translated honestly, was: this will make that stop happening. A promise about an absence. There is no demo for an absence — no screenshot, no burndown, no moment in a review where anyone claps.

Then the system went down badly enough that the question changed from whether the work had value to whether I could take a look.

The framework did the unglamorous thing. It refused to let work proceed until something other than the author had checked it. It ran the actual application in a browser rather than asking an agent whether it was satisfied. The crashes stopped. The project shipped.

Nobody remembers this, which is normal. Rescues get remembered as events, not as authorship.

Then the vocabulary showed up

On 11 February 2026, OpenAI published a piece on harness engineering: repository knowledge as the system of record, plans as first-class artifacts with decision logs committed to git.

On 24 March 2026, Anthropic published one on harness design: a planner, a generator and an evaluator kept deliberately apart, because an agent asked to grade its own work will praise it.

On 4 July 2026, someone finally named the other half. Graph engineering: designing agentic systems as explicit graphs instead of implicit loops. Nodes as units of capability. Edges as typed transitions carrying state. State as a checkpointed object rather than whatever survived in the context window.

Read that back. Nodes, typed edges, checkpointed state, an evaluator outside the generator, gates that can refuse. That is the thing we could not explain in November, described in a vocabulary that arrived eight months later.

The first commit is dated 21 January 2026. By 17 February the framework had taken a real production project end to end. There is a git history, which is more than most people have when they say they were early.

And precision matters here, because precision is what makes it defensible: OpenAI describe work that began in August 2025, before ours. This is not precedence. It is convergence — different people hitting the same failure modes and arriving at the same structure, with nothing public to copy from.

What I actually took from it

Not "trust your instincts." That is a poster, not a lesson.

The instinct was fine. The sequencing was terrible. We were working in a category with no name, and an unnamed category cannot survive a budget conversation — there is nothing for the other person to hold on to. My team lead was not failing to see something obvious. I was failing to make it visible.

What I would do differently

Name the thing, then bolt it to a number already bleeding on someone's dashboard — crashes per week, hours lost to rework — on day one. Not to win the argument later. To make the work legible while there is still a choice about whether to fund it.
