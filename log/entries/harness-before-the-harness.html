In January I was building something my stakeholders could not see the point of.

A QA agent. Gates between stages. A reviewer that was not the same agent that wrote the thing. Artifacts handed forward with IDs so you could trace any decision back to where it came from. From the outside it looked like I was building paperwork while everyone else was shipping features.

The conversation about whether I was worth keeping was not hypothetical.

Meanwhile the actual approach on the project was the one everybody was excited about: agents let loose, no gate, no verification, ship what comes out. It produced a lot of code very fast. It also brought the system down every few days, and every few days someone spent a night finding out why.

Then the call came. Could I take a look.

The pipeline I had been quietly building did the boring thing: it refused to let work move forward until something other than the author had checked it, and it ran the actual application in a browser rather than asking the agent whether it was happy. The crashes stopped. The project shipped.

Nobody remembers this. Rescues get remembered as events, not as authorship, and prevention is invisible by construction — the outage that does not happen leaves no trace, no incident channel, no war story.

The part I did not expect

On 11 February, OpenAI published a piece describing repository knowledge as the system of record, plans as first-class artifacts with decision logs checked into git. On 24 March, Anthropic published one describing a planner, a generator, and an evaluator kept deliberately separate, because an agent asked to grade its own work will praise it.

Four mechanisms. The same four I had running since January: context reset instead of compaction, state in files rather than in a conversation, an evaluator outside the generator, explicit criteria for what "done" means.

My first commit is dated 21 January. By 17 February the pipeline had processed a real production project end to end. I have the git log, which is more than most people have when they say they were early.

But I want to be precise, because the precise version is stronger. OpenAI describe work that started in August 2025 — months before mine. Nothing was public in January. So this is not precedence. It is convergence: two teams looking at the same failure modes, arriving at the same fixes, with nothing to copy from.

What I actually took from it

Not "trust your instincts." That is a poster, not a lesson.

The lesson is that my instinct was fine and my sequencing was terrible. Process work has no visible counterfactual, so it looks like nothing until the thing it prevents finally happens. I let it stay invisible until the system was on fire, and then I was right in the most expensive way available.

What I would do differently

Attach the unglamorous work to a number that is already bleeding on someone's dashboard, on day one. Not to prove a point later — to make the value legible while there is still a choice about whether to fund it.
