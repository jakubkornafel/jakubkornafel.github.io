I nearly got fired for building a category that had no name yet

In January I built an agentic SDLC framework. My team lead could not see the value in it, and he was not being unreasonable — the vocabulary for what it was would not exist for another six months.

"I don't see the value."

My team lead said it plainly, more than once, and he was not being difficult. He was describing the situation accurately. I was several weeks into building something I could not name, whose entire output was the absence of things going wrong.

Try defending that in a conversation about headcount.

What it actually was

Not an agent. Not a script that calls a model in a loop. What I was building was an agentic SDLC framework: the whole path from a raw idea to an implementable architecture package, decomposed into specialised roles that hand work to each other under rules.

Structurally it was a graph. Each role was a node — research, reverse engineering, product definition, architecture, a reviewer that was deliberately not any of them. The edges between them were typed: an artifact moved forward only if it carried the identifiers that let you trace every claim back to where it came from. State lived in files that survived the death of any individual run, so nothing important lived inside a conversation window. Transitions were gated, and a gate could say no and send the work back to a specific earlier node.

I did not have language for any of that in January. I described it as "the pipeline" and watched people's eyes glaze.

Why nobody could see it

The team's approach at the time was the exciting one: agents let loose on the codebase, no gate, no independent verification, ship whatever comes out. It produced a great deal of code very quickly. It also took the system down every few days, and every few days somebody lost an evening working out why.

My framework's pitch, translated honestly, was: this will make that stop happening. Which is a promise about an absence. There is no demo for an absence. No screenshot, no burndown chart, no moment in a sprint review where anyone claps.

Then the system went down badly enough that the question changed from whether my work had value to whether I could take a look.

The pipeline did the unglamorous thing. It refused to let work proceed until something other than the author had checked it. It ran the actual application in a browser instead of asking an agent whether it was satisfied. The crashes stopped. The project shipped.

Nobody remembers this, which is normal. Rescues get remembered as events, not as authorship.

Then the vocabulary showed up

On 11 February, OpenAI published a piece on harness engineering: repository knowledge as the system of record, plans as first-class artifacts with decision logs committed to git.

On 24 March, Anthropic published one on harness design: a planner, a generator, and an evaluator kept deliberately apart, because an agent asked to grade its own work will praise it.

On 4 July, someone finally named the other half. Graph engineering: designing agentic systems as explicit graphs instead of implicit loops. Nodes as units of capability. Edges as typed transitions carrying state. State as a checkpointed object rather than whatever survived in the context window.

Read that list back. Nodes, typed edges, checkpointed state, an evaluator outside the generator, gates that can refuse. That was the thing I could not explain in January, described in a vocabulary that did not exist yet.

My first commit is dated 21 January. By 17 February the framework had taken a real production project end to end. I have the git history, which is more than most people have when they say they were early.

And I want to be precise, because precision is what makes it defensible: OpenAI describe work that began in August 2025, months before mine. This is not precedence. It is convergence — different people hitting the same failure modes and arriving at the same structure, with nothing public to copy from.

What I actually took from it

Not "trust your instincts." That is a poster, not a lesson.

My instinct was fine. My sequencing was terrible. I was working in a category with no name, and an unnamed category cannot survive a budget conversation — there is nothing for the other person to hold. My team lead was not failing to see something obvious. I was failing to make it visible.

What I would do differently

Name the thing, then bolt it to a number that is already bleeding on someone's dashboard — crashes per week, hours lost to rework — on day one. Not to win the argument later. To make the work legible while there is still a choice about whether to fund it.
